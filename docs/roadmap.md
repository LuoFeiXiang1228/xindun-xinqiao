# 开发路线

按阶段推进，不承诺未经确认的学校、人员、时间表或效果。

| 阶段 | 输出 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：公开原型（当前） | 离线演示、公开设计、规则测试；许可与署名已确认 | 创建仓库，公开内容审阅 |
| B：虚构场景验证 | 任务清单、可用性反馈、误解修订 | 使用者能理解提示与责任分工 |
| C：后端最小闭环 | 身份认证、服务端授权、任务状态与审计 | 越权、撤销、删除及恢复测试通过 |
| D：机构评审 | 数据流、授权文案、责任与人工处理流程 | 实施方审核并明确必要授权 |
| E：受控试用 | 已授权范围内的小规模验证 | 安全评估、退出机制与应急流程可用 |

## 工程工作优先级

1. 明确权限和状态机，先实现拒绝路径，再增加便捷功能。
2. 通过服务端验证账号、任务分派、用途和有效期。
3. 加入撤销、删除、受控导出与审计，测试备份恢复。
4. 在人工流程稳定后，再评估通知、机构身份对接与模型辅助的必要性。

## 上线前检查

- 没有真实数据进入公开仓库、构建资源或日志。
- 没有把示例阈值当成经过验证的健康规则。
- 不在公共托管静态页面处理真实记录。
- 授权矩阵已转为服务端限制，直接请求接口也不能越权。
- 自用核对与协作记录的用途和访问边界清楚。
- 授权撤销、人员离岗、导出与备份删除规则经过验证。
- 已指定人工受理人并明确响应安排；演示不能承担求助受理。
