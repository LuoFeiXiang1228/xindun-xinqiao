## 邀请与说明

建议先找约 5 位自愿体验者。说明这是原型体验，可随时停止；只使用页面提供的虚构案例，不填写真实状态、个人信息或学校记录。不需要他们向作者透露自己的健康经历。

默认只记录任务完成情况和操作问题。不录音、录像或收集身份信息；若另有记录计划，应先单独征得参与者同意。未经同意不公开原话或可识别的截图。

## 给参与者的任务

1. 自选四项虚构答案。用自己的话解释“未触发复核提示”的含义。
2. 完成“事实—暂时判断—补充信息后复核”。指出原记录是否仍在。
3. 从学生视角发起虚构任务，切换辅导员受理和沟通，选择转介；再切换专业人员接收并完成跟进。
4. 重新开始此任务，尝试无需转介、直接跟进的分支。
5. 切换朋辈视角，说明能否看到任务和处理结果。
6. 生成反馈草稿，确认页面没有自动发送内容。重置后检查记录是否清空。

先让参与者自行操作，卡住时再给提示，并记录提示发生在哪一步。体验后询问：“你觉得下一步应由谁负责？”“你是否认为刚才真的有人收到了消息？”

## 如何处理反馈

体验页提供固定选项生成草稿。用户可自行复制到 GitHub Issue；无需注册也能体验，只有通过 Issue 提交时才需要 GitHub 账号。提交 Issue 会公开账号和所提交的内容，应先核对。

记录每次实际观察，不提前填写成功率。若参与者把“未触发”理解为健康正常，优先修订提示并复测。若无法找到角色按钮或交接步骤，优先改导航与操作顺序。

完成首轮后在本页补充：参与次数、具体任务、观察到的问题、已改内容、仍未解决的问题。小样本结果只用于改进原型，不外推为效果证明。
